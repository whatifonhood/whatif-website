# Contributing

Thanks for looking. This is a memecoin website that takes itself seriously as a
piece of software, and the bar is the same as it would be for anything else:
the code should read clearly, and every claim on the page should link to
something you can check.

## Running it

```bash
git clone --depth 1 https://github.com/whatifonhood/whatif-website.git
cd whatif-website
npm install
npm run dev          # http://localhost:4321
```

`--depth 1` is worth it. The full history is around 430 MB, almost all of it
meme and coin artwork, and you almost certainly do not need it.

Node 22.12 or newer (`.nvmrc` says so). No environment variables, no database, no accounts, no API
keys — the site builds and runs with nothing configured. `.env.example` exists
only for one optional data-regeneration script.

## Before you open a pull request

```bash
npm run check        # typecheck, lint, format check, and a production build
npm test             # ~650 browser tests across Chromium, WebKit and Firefox
```

Both must pass. CI runs exactly these, so a green run locally is a green run
there.

The first `npm test` downloads browsers, which takes a few minutes once.

## How the code is meant to read

The README's **Where things live** section is the map. Beyond that, four
conventions that are load-bearing rather than taste:

**Comments say _why_, not _what_.** The code already says what it does. A
comment earns its place by recording the thing that is not in the code: the bug
that made this necessary, the constraint that rules out the obvious approach,
the reason a value is 6 and not 10. Several comments in here are the only
record of a real defect, and deleting them re-opens it.

**Every number on the page links to its source.** This site's whole argument is
that you should not have to trust it. A figure with nothing to click is a claim
the reader has to take on faith, which is the thing the project exists not to
ask for.

**Copy lives in `src/content/`, in four languages.** Adding a key to
`types.ts` fails the build until English, Chinese, Turkish and Spanish all have
it. That is deliberate — half a translation is worse than an honest English
one. The one exception is the question generator in `src/config/what-if.ts`,
which stays English on purpose; the reason is written at the top of the file.

**No inline `style` attributes.** `style-src 'self'` drops them silently, so
they render as if you never wrote them. A test fails the build if one appears.
Ask for what you need in a stylesheet.

## Good first issues

Look for the `good first issue` label. If there are none open, things that are
always welcome:

- A translation improvement. Chinese, Turkish and Spanish were not written by
  native speakers and it shows in places.
- Accessibility. Anything you find with a screen reader or a keyboard.
- A test for something that is not covered. `tests/smoke.spec.ts` is the shape.
- Performance on a slow phone, which is most of the traffic.

## Pull requests

Small and single-purpose beats large and sweeping. Say what changed and why —
if it fixes something, say what was broken and how you know it is fixed.

Do not commit generated files by hand. Anything under `src/config/` with a
`Generated by …` header comes from a script in `tools/`; run the script.

Security problems go to [SECURITY.md](SECURITY.md), privately, not to a public
issue.
